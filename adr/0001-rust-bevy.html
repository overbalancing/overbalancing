ADR 0001: Rust and Bevy

Status: accepted. Created: 2026-10-18. Accepted by Marc-Hendric Lühr on 2026-10-19. The owner must merge this acceptance change.

Context

Overpalancing is a commercial game, initially developed on Linux with Windows, macOS, iOS and Android build coverage. The owner has selected Rust and Bevy; this proposal records the implementation consequences without claiming ADR approval.

Decision

Use Bevy 0.20.0 and Rust 1.99.0 stable, with an initial MSRV of 1.97.1 matching Bevy. Nightly means a scheduled nightly MSRV workflow, not the nightly Rust compiler. Pin the toolchain and dependency lockfile. Separate a dependency-free deterministic domain crate from the Bevy application crate. Share application startup across desktop and mobile; build the mobile library as a cdylib with Bevy's bevy_main entrypoint.

Select explicit 2D rendering, windowing and font features. Linux enables X11 and Wayland; Android uses native-activity. Use Bevy primitives for the initial view, with no external art or physics dependency. Prototype rendering must not implement undocumented game rules.

Alternatives

Godot provides mature visual tooling and mobile export but would change the owner's engine choice. Macroquad offers a smaller 2D API but less integrated ECS and tooling. A custom wgpu engine would transfer rendering and platform integration costs to this project. No alternative is added as a dependency.

Consequences and risks

Bevy's pre-1.0 releases can introduce breaking APIs. Cross-compilation is build evidence; simulator, device and store-signing validation remain separate. Mobile packaging requires platform SDKs and signing credentials before distribution. Keep dependency health under recurring review; additional crates need owner confirmation after an architect assessment.

Current audit reports no known vulnerability but reports an unmaintained transitive ttf-parser 0.25.1 advisory, RUSTSEC-2026-0192. Do not suppress this silently; track upstream resolution and recheck the locked graph.
