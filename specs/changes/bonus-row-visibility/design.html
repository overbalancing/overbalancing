Expanded rendering and inspection

The renderer currently slices each stack after a shared inspection offset. Replace the fixed nine-ball limit with nine plus the board's earned bonus-row count. This maximum visible window is ten, eleven or twelve rows after expansion; individual heavy/balanced/light capacities remain core-owned.

Preserve the original cell identity as lane plus offset plus visible index. Draw the slice relative to the same platform and row height, so clear glow and matching references continue to address the retained core ball. Do not delete, recreate or reweight core balls to repair visibility.

Derive the maximum scroll offset from the longest stack minus the same expanded visible window, with saturating subtraction. Clamp a previously valid offset when a clear or other board change shortens the stack, even when no new scrolling input arrives. Otherwise a stale offset can hide retained bottom balls after the clear.

The existing bonus-aware camera framing, input coordinate mapping, platform positions, preview/chute layout, transit targets and glow identities must remain consistent. Actual render review is required to rule out camera clipping; headless entity checks alone establish construction, not visible pixels.

Acceptance

  • Expanded heavy, balanced and raised stack fixtures create all twelve, eleven and ten occupied ball entities with their original indices.
  • Base rendering still creates nine visible rows and preserves original identities while scrolling.
  • Overflow inspection uses the expanded window and clamps back after the stack shrinks without extra input.
  • Actual desktop and narrow portrait images show the highest retained balls, all previews and the chute without clipping.
  • Core files, capacities, matching and input/drop behavior remain unchanged.
