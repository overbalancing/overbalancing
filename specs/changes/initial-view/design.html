Proposal · Design · Tasks · Scenarios · All specifications

Scene and readability

Use four visibly separate seesaws with recognizable pivots, a dispenser above the board, and balls with visible numeric weights. Present color with an additional textual or geometric cue so color alone is not required. Multicolor samples, if displayed, must show each constituent color without implying an unresolved matching algorithm.

Input and layout

Support keyboard and pointer input on desktop and touch input on mobile. Provide visible instructions describing the implemented chute-selection demo controls. Keep the board and controls usable after window resizing and in portrait and landscape layouts. UI interactions must not accidentally trigger a board action behind a control.

Scope and assets

Primitive shapes and built-in text are sufficient; no external asset request is needed. The first view demonstrates chute selection only; ball dropping, gameplay resolution and validated physics are deferred.
