Architecture and dependency assessment

Checked 2026-10-18. Proposed ADRs require owner-controlled approval.

Boundaries

The core crate owns deterministic domain data and future game rules. It has no Bevy or operating-system dependency. The app crate owns presentation, input, window lifecycle and platform entrypoints. One shared startup function serves desktop binaries and mobile libraries. Primitive rendering is sufficient for the first scene; assets will be requested with purpose and pixel dimensions when needed.

Bevy assessment

Criterion Assessment
Version and activity 0.20.0, released 2026-10-08, is the selected baseline. Pin and test upgrades rather than assuming API compatibility.
Bus factor Organization-maintained with distributed contributors and public governance; materially lower single-maintainer risk than a personal engine. Maintainer concentration in specialized subsystems remains a risk; a numeric bus factor is not established.
Reputation Established Rust ECS engine with official cross-platform examples and a public release process. Popularity is supporting evidence, not a safety guarantee.
License MIT OR Apache-2.0; preserve required dependency notices for distribution.
Alternatives Godot: mature editor and export pipeline, different engine ecosystem. Macroquad: smaller 2D surface, less integrated ECS. wgpu: rendering substrate requiring substantially more platform and engine work.
Decision authority Rust and Bevy were selected by the owner. No new direct runtime crates are proposed.

Dependency risk register

The locked graph currently reports an unmaintained ttf-parser 0.25.1 dependency under RUSTSEC-2026-0192. cargo audit reports no known vulnerabilities. Keep this warning visible and check upstream replacements; an unmaintained warning alone does not establish an exploitable vulnerability. Audit and deny run continuously, with Renovate proposing dependency updates.

Platform evidence

Linux is the development platform. CI must build Windows, macOS, Android and iOS in addition to Linux. Compilation does not prove store packaging, signing, touch usability or device rendering; retain these as explicit release checks. MSRV runs on the nightly schedule using stable Rust 1.97.1; development uses stable Rust 1.99.0.
